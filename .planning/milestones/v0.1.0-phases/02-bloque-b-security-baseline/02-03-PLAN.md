<threat_model>

## Trust Boundaries

| Boundary                                     | Description                                                                                                 |
| -------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| git history → external clones                | Any commit in main is visible to forks/clones forever — rewriting does not retroactively remove from clones |
| developer workstation → external service     | Rotated tokens require admin action on the external service (GitHub/Codecov/PyPI/etc.)                      |
| GitHub Settings UI → branch protection rules | Required status checks names must EXACTLY match job `name:` values from the workflow                        |

## STRIDE Threat Register

| Threat ID           | Category                           | Component           | Disposition | Mitigation Plan                                                                                                                                                                                                                                                                                                                              |
| ------------------- | ---------------------------------- | ------------------- | ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T-SEC-04-leak       | Information Disclosure             | git history         | mitigate    | Run `gitleaks detect --source . --no-git=false` once locally (Task 02-03-01) to enumerate any historical secrets; for each real finding rotate the token at the external service, then add the fingerprint to `.gitleaksignore` as "rotated YYYY-MM-DD" — NEVER reuse the token, NEVER rewrite history (D-04 + REQUIREMENTS.md Risks policy) |
| T-SEC-05-sast       | Tampering / Information Disclosure | addons/ Python code | mitigate    | Run `bandit -r addons/ -lll -iii` (Task 02-03-02); zero HIGH findings is the gate. MEDIUM/LOW findings recorded in BUGS_BACKLOG.md so they are visible but non-blocking per D-02 (escalation to MEDIUM deferred to post-Fase 2 EDI when crypto code exists)                                                                                  |
| T-SEC-04-replay     | Repudiation                        | rotated tokens      | accept      | Rotated tokens remain in history but are invalidated upstream; risk of replay = 0 once rotation completes. `.gitleaksignore` entry includes rotation date for audit trail                                                                                                                                                                    |
| T-SEC-03-protection | Elevation of Privilege             | direct push to main | mitigate    | After workflow proven green, add jobs `gitleaks`, `bandit`, `dependency-review` to required status checks list in branch protection rule for `main` (Task 02-03-03 — manual UI step) so future PRs cannot merge with red security checks                                                                                                     |

</threat_model>

  <name>Task 02-03-01: Run gitleaks full-history scan locally, rotate any live secrets, write .gitleaksignore if needed</name>
  <files>.gitleaksignore</files>
  <read_first>
    - .planning/phases/02-bloque-b-security-baseline/02-CONTEXT.md §"Workflow security.yml shape" D-04 (scope decision) + §Deferred (rewrite-history policy explicitly rejected)
    - .planning/phases/02-bloque-b-security-baseline/02-RESEARCH.md §"gitleaks History Strategy" (decision tree rotate-vs-rewrite, .gitleaksignore syntax, PowerShell+Docker invocation)
    - .planning/phases/02-bloque-b-security-baseline/02-PATTERNS.md §".gitleaksignore" (file format, pitfalls)
    - .planning/REQUIREMENTS.md §"Risks" (line: "tokens reales detectados se rotan (NO se reescribe git history)")
  </read_first>
  <action>
    Run `gitleaks detect --source . --no-git=false --report-format sarif --report-path gitleaks-local-baseline.sarif` locally (NOT in CI) to scan the FULL history of the repo. On Windows use the Docker invocation from 02-RESEARCH.md §"Cómo ejecutar gitleaks localmente":

    `docker run --rm -v "${PWD}:/repo" ghcr.io/gitleaks/gitleaks:latest detect --source /repo --no-git=false --report-format sarif --report-path /repo/gitleaks-local-baseline.sarif`

    Parse the resulting `gitleaks-local-baseline.sarif`. For each finding:

    - **Real secret (active token):** ROTATE FIRST via the external service's dashboard (GitHub PAT → Settings → Developer settings → Personal access tokens → Regenerate; Codecov → Settings → Tokens; etc.). DO NOT proceed to the next steps until rotation is confirmed and the new token works. Then add the finding's `Fingerprint` (exact string from SARIF `properties.fingerprint` field or JSON output) to `.gitleaksignore` with a header comment like `# rotated 2026-06-02 — <service name> token regenerated`.
    - **False positive (test key, example, placeholder):** Add the fingerprint to `.gitleaksignore` with header comment `# false positive 2026-06-02 — <reason>`.
    - **No findings:** DO NOT create `.gitleaksignore`. The file exists ONLY if there is content to allowlist. Leave the workspace clean.

    NEVER run `git filter-repo`, `git filter-branch`, or BFG Repo-Cleaner. NEVER force-push to `main`. NEVER use `.gitleaksignore` to suppress a token that has not been rotated.

    Delete the temporary `gitleaks-local-baseline.sarif` before committing (it is not an artifact we keep in repo — `git ls-files | grep gitleaks-local-baseline` must return empty).

    Commit (if `.gitleaksignore` was created): `chore(sec): add .gitleaksignore for rotated historical tokens (SEC-04)`. If there were no findings, this task produces no file change — record the result in the plan SUMMARY ("0 findings on full-history scan; no .gitleaksignore needed") and proceed to the next task.

  </action>
  <acceptance_criteria>
    - `gitleaks detect --source . --no-git=false --report-format sarif --report-path gitleaks-local-baseline.sarif` ran to completion (or its Docker equivalent on Windows)
    - For every finding in `gitleaks-local-baseline.sarif` flagged as a real secret, the token has been rotated at the external service (proof: new token works, old token rejected — record in SUMMARY)
    - `Test-Path gitleaks-local-baseline.sarif` returns `False` (temp file removed before commit)
    - If `.gitleaksignore` is created: header comment includes date + reason for each entry; format is `<sha>:<path>:<rule-id>:<line>` per line
    - `git filter-repo` / `git filter-branch` / BFG were NOT executed (verify: `git reflog --all | Select-String 'filter-repo|filter-branch|BFG' -Quiet` returns `False`)
    - `git log --oneline main..HEAD | Measure-Object -Line` shows new commits do NOT exceed the count of intentional commits (no rewrite of historical commits)
    - After this task + push to PR branch: the `gitleaks` job in `.github/workflows/security.yml` returns `success` (because `.gitleaksignore` covers any historical findings)
  </acceptance_criteria>
  <verify>
    <automated>powershell -NoProfile -Command "$wasRewrite = (git reflog --all 2>&1 | Select-String 'filter-repo|filter-branch|BFG' -Quiet); if ($wasRewrite) { Write-Host 'History rewrite detected — POLICY VIOLATION'; exit 1 }; $tempLeft = Test-Path gitleaks-local-baseline.sarif; if ($tempLeft) { Write-Host 'Temp SARIF still present — clean up before commit'; exit 1 }; exit 0"</automated>
  </verify>
  <done>Full-history gitleaks scan executed; any live secrets rotated; .gitleaksignore created only if needed with dated reasons; no history rewrite.</done>
