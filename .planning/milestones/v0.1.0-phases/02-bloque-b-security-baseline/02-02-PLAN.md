<threat_model>

## Trust Boundaries

| Boundary                        | Description                                                                    |
| ------------------------------- | ------------------------------------------------------------------------------ |
| developer → PR                  | Untrusted commit content (may contain secrets, vulnerable deps, insecure code) |
| GitHub Action runner → workflow | Pinned action versions must come from trusted publishers                       |
| workflow → Security tab         | SARIF upload crosses into GitHub's code-scanning subsystem                     |

## STRIDE Threat Register

| Threat ID          | Category               | Component               | Disposition | Mitigation Plan                                                                                                                                                                                                                                                                                                                         |
| ------------------ | ---------------------- | ----------------------- | ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T-SEC-03-noscan    | Information Disclosure | PRs reaching main       | mitigate    | Workflow runs on every `pull_request` to main + every `push` to main with 3 parallel scans (Task 02-02-01); branch protection (Plan 03) adds these jobs to required status checks so PRs cannot merge if any scan fails                                                                                                                 |
| T-SEC-03-supply    | Tampering              | GitHub Action versions  | mitigate    | Pin every `uses:` to a verified tag from a known publisher: `gitleaks/gitleaks-action@v3` (A-02), `actions/dependency-review-action@v4` (research §Action Pins), `github/codeql-action/upload-sarif@v3` (D-03), `actions/checkout@v4` + `actions/setup-python@v5` (Phase 1 pins). Future hardening (SHA-pinning) deferred to Pre-Fase 3 |
| T-SEC-03-sarif     | Information Disclosure | Security tab visibility | mitigate    | Each upload-sarif step has distinct `category:` (`gitleaks` vs `bandit`) so neither overwrites the other in the Security tab (mandatory since July 2025 per GitHub docs cited in RESEARCH.md §Action Pins)                                                                                                                              |
| T-SEC-03-prcomment | Information Disclosure | gitleaks PR comments    | mitigate    | `GITLEAKS_ENABLE_COMMENTS: "false"` (D-01 rationale: avoid noise / accidental leak of finding text in PR comments)                                                                                                                                                                                                                      |

</threat_model>
